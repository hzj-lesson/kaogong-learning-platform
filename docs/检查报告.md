## 四、发现的问题与改进建议

### 1. 🐛 文案模板残留（必须修改）

**位置**：第 3253 行  
**当前文案**：
```html
<div class="empty-hint">还没有日志，学完第一个 SQL 就来记一条吧。</div>
```
**问题**：这是一个考公学习平台，不是 SQL 学习平台，"SQL" 明显是模板未清理干净的残留。  
**建议**：改为「还没有日志，学完第一个任务就来记一条吧。」

---

### 2. ⚠️ 标题版本描述不一致

**问题**：
- `<title>` 标签写的是「考公学习平台 · **2028 国考冲刺版**」
- 顶部品牌栏写的是「考公学习平台 · **2028 国考备考版**」

**建议**：统一为同一版本描述，避免用户困惑。

---

### 3. ⚠️ 打卡弹窗按钮文案与行为不符

**位置**：第 2883–2895 行  
**问题**：「✔ 打卡并记录」与「只打卡」两个按钮绑定的是**同一个回调函数** `doCheckin`，行为完全一致，都不会记录额外日志。  
**建议**：要么两个按钮合并为「打卡」，要么为「打卡并记录」增加日志输入/备注字段，让行为匹配文案。

---

### 4. ⚠️ B 站资源链接不够具体

**位置**：资源列表第 2749–2759 行  
**问题**：「李梦圆申论」「花生十三」「刘文超Vincent」三个 B 站 UP 主链接都是通用首页 `https://space.bilibili.com/`，没有指向具体空间。  
**建议**：补充具体 UP 主 space ID 的完整链接，或在描述里加上搜索关键词，让用户知道如何找到。

---

### 5. 💡 可改进：进一步转义用户输入

**问题**：应用大量使用了 `innerHTML` 拼接界面。虽然日志、错题、笔记等用户输入已使用 `esc()` 转义，搜索高亮也做了转义，整体风险较低，但自定义导入的 JSON 中若包含 HTML/JS，仍可能在渲染时被 `innerHTML` 执行。  
**建议**：导入备份后对 `notes`、`logs[].text`、`wrong[].reason` 等用户可控字段做一次转义或纯文本处理；对固定数据则保持当前 HTML 富文本渲染。

---

### 6. 💡 可改进：番茄钟完成后的累计逻辑

**问题**：番茄钟仅在 `work` 模式自然结束时累计时长，若用户中途点击「重置」或「跳过」则不计入。这是设计选择，但可能对用户不够友好。  
**建议**：若希望更宽松，可考虑「重置」时按已专注时间按比例计入，或在 UI 中明确提示「跳过/重置不计入累计」。

---

## 五、优秀设计点

1. **本地优先 + 数据主权明确**：所有数据仅存浏览器，不联网，首次打开即提醒备份。
2. **快照恢复机制**：导入前、重置前自动保存快照，降低误操作损失。
3. **番茄钟校准策略**：用 `endAt` 时间戳而非每秒 tick 累加，避免后台节流或休眠导致的时间丢失。
4. **知识点体系完整**：32 个任务全部配有 `intro`、`points`、`pitfalls`、`quiz`、`answer`、`deep tasks`，学习路径清晰。
5. **键盘快捷键**：数字键切 tab、Esc 关弹窗，效率友好。
